# 文衡网页版多人协作

[English guide](../CONTRIBUTING.md) · [发布与凭据隔离](RELEASE_SECURITY.zh-CN.md)

本流程只覆盖 `pasariga/multi_model_essay` 的网页前端、后端及相关配置。
不涉及历史项目妙笔智改（简称智笔）、OpenEssayScore、训练任务、DSW 或私有模型归档。

## 邀请同学

仓库所有者在 GitHub 的 **Settings → Collaborators → Add people** 输入同学的
GitHub 用户名。同学接受邀请后，使用自己的账号修改代码。个人账号仓库的普通
Collaborator 通常具有写权限，但不应获得管理员权限；不要共享所有者账号。
当前没有提供待邀请的同学账号，因此本轮不猜测用户名、不发送邀请。

仓库当前是公开仓库，本次没有改变可见性。邀请码不等于服务器访问权；同学不需要
root、ECS 密码、生产 SSH 私钥、云平台密钥或数据库密码。

## 一次修改如何提交

1. 从最新 `main` 创建自己的分支，例如 `feature/zhangsan-report-layout`、
   `fix/lisi-upload-error` 或 `docs/wangwu-local-setup`。
2. 只修改本次需求的文件。在本地使用测试配置和虚构示例，不复制生产 `.env`、
   学生作文、数据库备份、上传目录或模型文件。
3. 检查文件差异，提交并推送自己的分支。
4. 发起目标为 `main` 的 Pull Request，写清修改内容、验证过程和发布影响。
5. 查看 **Checks**。失败时修复自己的分支并重新推送；CI 自动重新检查。
6. 等待 `@pasariga` 审核。处理评论、解决讨论；新提交会使旧批准失效。
7. 检查通过且审核完成后使用 **Squash and merge**。合并不会发布生产网站。

每项需求使用独立分支，不在别人的分支上强推。多人修改同一文件时先协调，冲突
在开发分支解决，不能通过强推 `main` 覆盖别人的修改。

## 常用编辑方式

### VS Code

登录自己的 GitHub 账号 → **Git: Clone** 克隆仓库 → 左下角分支菜单创建分支 →
编辑 → 源代码管理中逐项检查并暂存 → 提交 → 发布分支 → 在 GitHub 创建 PR。
也可使用英文指南中的 Git 命令。没有额外购买或安装 Codespaces 的要求。

### Codex

打开自己的本地仓库，先切到自己的分支。说明需求及“仅修改文衡网页版，不部署，
不接触生产凭据和模型项目”。让 Codex 展示改动和验证结果，自己复查后提交 PR。
助手生成的代码同样必须经过 CI 和代码审查，不自动视为可信。

### GitHub 网页编辑器

打开文件点击编辑，提交时选择 **Create a new branch for this commit and start a
pull request**。需要多文件编辑时可按 `.` 打开 github.dev；网页编辑器没有完整
本地后端环境，推送后以 CI 结果作为反馈。

## 自动检查内容与边界

- **Frontend checks：**按锁文件安装依赖、Vue/TypeScript 类型检查、生产构建。
- **Backend checks：**Python 语法、临时 PostgreSQL 16 数据库迁移和现有网页测试。
  该测试数据库随 GitHub 临时 Runner 销毁，不是生产数据库。
- **Repository safety：**常见误提交凭据模式、敏感文件路径和部署脚本语法。

CI 不持有生产密钥，不下载或验证 Paddle 模型，不连接 DSW，不调用真实付费模型
服务。前端尚未定义单元测试，不能把构建成功写成所有浏览器交互已验证。
凭据检查仅覆盖常见模式，不能保证发现所有秘密。

## 所有者怎样审核

查看 PR 的 **Files changed**，核对需求与范围；特别检查权限、依赖、数据库迁移、
API 兼容性和 `.github/**` 改动。确认测试真正通过、失败没有被忽略；涉及界面的
修改查看截图或本地验证。所有文件均由 `@pasariga` 担任 Code Owner。

`main` 禁止普通协作者直推、强推和删除，要求通过三个检查、代码所有者批准并解决
讨论。所有者保留管理员恢复能力，这是明确的权限边界，不对同学开放。
所有者自己的 PR 不能自批；日常可由另一位合适审核者审核。初始配置若使用所有者
管理员合并，也应先检查 CI，且不代表批准上线。

即使同学有仓库写权限，生产凭据也仅位于受保护的 `production` 环境；开发分支
不能领取它们。不要把凭据挪到仓库级 Secrets，也不要添加能访问生产的自托管 Runner。
